# Evaluation Methodology

## Scientific boundary

ImageGuard reports indications and localization cues. `SUSPICIOUS_INDICATION`
is not a claim of forgery, and `NO_INDICATION` does not authenticate an image.
`INCONCLUSIVE` is a valid outcome and is reported separately from the binary
image metrics. ELA, EXIF, noise, frequency, and splicing cues cannot produce a
standalone `SUSPICIOUS_INDICATION` verdict.

## Image-level metrics

The primary positive class is `SUSPICIOUS_INDICATION`. `NO_INDICATION` and
`INCONCLUSIVE` are counted as non-positive for the binary confusion matrix;
the inconclusive count is reported separately so abstentions remain visible.
`NOT_APPLICABLE` and `ERROR` are excluded from that matrix and have separate
counts. A method exception or invalid sample is excluded and counted, never
silently converted to an authentic image.

Precision, recall, F1, specificity, and accuracy are reported with TP/FP/TN/FN.
If a required class is absent, its metric is `N/A` (`None` in JSON), not 0 or 1.

## Pixel-level metrics

- R1: score localization only where the ground-truth mask is non-empty.
- R2: a missing or empty predicted mask against a non-empty GT scores zero
  recall, F1, and IoU. It remains in the denominator.
- R3: a non-empty predicted mask on an authentic image is recorded as a false
  cue with its predicted-area ratio.
- R4: authentic images with no predicted cue are counted as clean controls and
  excluded from pixel aggregates.
- R5: an empty or single-class split reports unavailable class-dependent
  metrics as `N/A`.

ModelBench reports IoU and boundary-F1@8 for every edited sample with a
non-empty GT, counting a missing mask as zero; a predicted mask whose geometry
differs from the GT is left unscored and counted in `n_malformed_gt`. It
reports untouched originals in a separate control table with verdict counts,
non-empty-mask rate, and mean/max mask-area ratios. Those controls are useful
for false-cue screening but remain synthetic when generated by ModelForge;
they do not establish performance on camera photographs.

## Dataset and threshold protocol

Synthetic source images and all derivatives from one base image stay in one
split. Tune thresholds only on `dev`; do not use a locked `test` split for
calibration. CoMoFoD is an optional external dataset and must be downloaded and
its mask conventions verified before evaluation. Missing or malformed masks
are excluded and counted; they are never resized silently.

The ModelForge LaMa editor is used only to generate research examples. The
desktop app does not load LaMa as a forgery classifier. The `noise_local`
thresholds are provisional synthetic-data heuristics, not learned weights or a
real-photo calibration.

## Frozen CoMoFoD studies

Use the research entry point
[`scripts/evaluate_detector_quality.py`](../scripts/evaluate_detector_quality.py)
when a study needs a fixed sample inventory and a paired baseline/candidate
comparison. It wraps the existing evaluation runner; it does not change app
thresholds or detector behavior. `--help` lists the command options, while
`_lock_pair` and `compare` enforce the JSON contracts.

From the repository root in the project Python environment, choose fresh local
output paths:

```powershell
python scripts/evaluate_detector_quality.py freeze --root data/comofod_base --out reports/detector-quality-study/manifest.json --seed 42
python scripts/evaluate_detector_quality.py evaluate --manifest reports/detector-quality-study/manifest.json --split dev --config configs/thresholds.yaml --methods keypoint,block --out reports/detector-quality-study/baseline-dev
```

Freeze requires the dataset's `provenance.json`, matching file hashes and strict
non-empty binary masks. Review its exclusions before inference. Protocol v2 groups
variants by base ID and exact original RGB pixels and dimensions, checking both
stored and detector-normalized EXIF orientation.
Groups linked to prior exposure stay outside `locked`. Declare additional exposure
with `freeze --exposed`. When migrating a v1 study on the same inventory, pass its
sealed manifest with `freeze --prior-manifest`: v2 preserves prior dev rows and
sends their aliases to diagnostics. V1 manifests and reports remain historical
and are rejected for inference or comparison. Exact pixel equality does not catch
all related scenes. Keep official assets local under their research-use terms.

Each evaluation directory contains `report.json` and available predicted masks.
The report links per-image traces to the same method calls used for aggregates,
with manifest, protocol, source/import, config, runtime and seed identities.
Use those traces and excluded/error counts to check denominators; a headline
score alone is insufficient evidence. Output paths are not overwritten.
Use each row's `scene_id` to group repeated originals when reporting independent
sample counts and scene-weighted metrics alongside row totals.

Before opening `locked`, freeze the primary objective and user-approved
numerical tradeoffs from dev diagnosis. Locked inference requires a clean source
checkout, `--pair-contract` and `--role baseline|candidate`; the contract binds
manifest, protocol, seed, ordered methods, approved criteria hash and each
role's source/config hashes. A sealed consumption ledger next to the contract
binds each manifest/protocol cohort to a single `event_id` across roles; an
exclusive event-role receipt still prevents an ordinary repeat of that role.
`compare` checks the paired reports against the
preregistered criteria. Preserve interrupted events for review; do not change a
candidate after seeing test outputs and rerun it as an unseen evaluation.

These controls support reproducibility, not detector accuracy. Report observed
false positives, misses, abstention and localization limits with sample counts;
a successful study does not establish general real-photo performance.

## Provenance

`python -m imageguard eval` records experiment ID, seed, config hash, git SHA,
dataset version, scored/excluded counts, and per-method metrics.

ModelBench also records manifest and full dataset SHA-256, a source-tree
fingerprint, threshold hash, git SHA and working-tree state, generator backend,
seed, LaMa weight hash when supplied by the manifest, runtime versions, method
names, and each result's parameter hash. Reports from older ModelBench runs do
not contain all of this provenance; do not treat them as independently
reproducible evidence.
